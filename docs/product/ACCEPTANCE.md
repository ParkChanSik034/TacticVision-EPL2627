# MVP Acceptance Criteria

## 목적

이 문서는 TacticVision MVP 기능을 완료로 판정할 때 사용하는 검증 기준과
필요한 증거를 정의한다. 화면이 존재하거나 코드가 작성된 것만으로는 완료로
처리하지 않는다.

## 완료 판정 원칙

- 기능별 필수 조건과 공통 조건을 모두 충족해야 한다.
- 검증 결과는 해당 기능 Issue 또는 PR에 남긴다.
- 확인하지 못한 조건은 통과가 아니라 미검증으로 기록한다.
- 알려진 결함이 있으면 영향, 재현 방법과 후속 Issue를 함께 기록한다.
- 변경 사항이 `main`에 병합되기 전에는 최종 완료로 처리하지 않는다.

## 기능별 완료 조건

### Home 및 탐색

- [ ] Home이 새로고침 후 오류 없이 표시된다.
- [ ] 팀·선수·감독·경기 탐색 진입점이 보이고 키보드로 접근할 수 있다.
- [ ] 검색 결과가 입력어에 맞게 갱신되고 결과 선택 시 올바른 대상으로 이동한다.
- [ ] 검색 결과 없음과 데이터 로드 실패 상태가 구분되어 표시된다.
- [ ] 주요 카드와 CTA가 연결된 상세·비교·경기 화면으로 이동한다.

### 팀·선수·감독 상세 화면

- [ ] 지원 대상은 이름, 소속, 역할과 핵심 분석 정보를 표시한다.
- [ ] 상세 정보가 팀·선수·감독 JSON의 동일 ID와 연결된다.
- [ ] 대상 변경 후 이전 대상의 정보가 화면에 남지 않는다.
- [ ] 존재하지 않거나 불완전한 대상은 대체 상태를 표시하고 앱을 중단하지 않는다.
- [ ] 상세 화면에서 관련 비교 또는 전술 흐름으로 이동할 수 있다.

### Team·Player·Manager Compare

- [ ] 비교 대상을 검색·선택·해제·초기화할 수 있다.
- [ ] 허용된 최소·최대 선택 수를 UI가 안내하고 초과 선택을 막는다.
- [ ] 비교 항목이 동일한 데이터 계약과 단위로 정렬되어 표시된다.
- [ ] 선택이 없거나 데이터가 부족한 경우 안내 상태를 표시한다.
- [ ] 비교 대상의 상세 화면으로 이동해 동일한 정보를 확인할 수 있다.

### Match Hub 및 Match Lineups

- [ ] 선택한 경기의 팀, 일정, 장소와 핵심 정보가 일관되게 표시된다.
- [ ] 양 팀 라인업이 팀·선수 데이터의 유효한 ID 또는 문서화된 대체값을 사용한다.
- [ ] 포메이션 변경과 선수 교체가 현재 경기 상태에 반영된다.
- [ ] 라인업 데이터가 없거나 불완전한 경우 대체 상태를 표시한다.
- [ ] Match Hub에서 Tactical Board 또는 관련 비교 화면으로 이동할 수 있다.

### Tactical Board

- [ ] 팀과 포메이션을 선택하면 올바른 기본 배치가 표시된다.
- [ ] 선수 위치 또는 역할 변경이 화면과 현재 전술 상태에 반영된다.
- [ ] 초기화 후 선택한 포메이션의 기본 상태로 돌아간다.
- [ ] 잘못된 포메이션·선수·전술 데이터가 들어와도 보드 전체가 중단되지 않는다.
- [ ] 전술 분석 정보가 현재 선택한 팀·감독·포메이션과 일치한다.

## P1 공개 출시 게이트

아래 조건은 개별 P0 기능이 동작해도 공개 출시 전에 반드시 통과해야 한다.

- [x] 핵심 사용자 흐름 A를 데스크톱과 모바일에서 처음부터 끝까지 수행했다.
- [x] 핵심 사용자 흐름 B를 데스크톱과 모바일에서 처음부터 끝까지 수행했다.
- [x] 모든 JSON 파일의 구문, 필수 필드, ID 중복과 참조 무결성을 검증했다.
- [x] 지원 브라우저와 최소 화면 크기를 문서화하고 실제로 확인했다.
- [x] 치명적인 콘솔 오류, 실패한 핵심 요청과 알려지지 않은 404를 제거했다.
- [x] 배포 주소에서 로컬과 동일한 핵심 흐름을 확인했다.
- [x] 데이터 출처, 기준 시점, 라이선스와 알려진 한계를 문서화했다.

## 검증 기록 형식

각 기능 Issue 또는 PR에는 다음 형식으로 결과를 남긴다.

```markdown
## Verification

- 검증 환경: 브라우저 / 화면 크기 / 배포 또는 로컬 주소
- 사용 데이터: 파일 또는 데이터 버전
- 수행 경로: 사용자가 실행한 단계
- 통과 조건: AC ID와 기능별 체크 항목
- 미검증 항목: 확인하지 못한 조건과 이유
- 알려진 문제: 영향과 후속 Issue
- 증거: 스크린샷, 영상, 로그 또는 PR 링크
```

## 완료와 범위 확정의 차이

MVP 범위 체크는 기능을 만들기로 결정했다는 뜻이다. 이 문서의 조건과 증거를
모두 충족한 뒤에만 해당 기능의 구현 완료 체크를 할 수 있다.
